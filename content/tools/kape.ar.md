# أداة KAPE — الدليل الكامل للتقصي الجنائي الرقمي السريع (Digital Forensics Triage)

تُعد أداة `KAPE` (Kroll Artifact Parser and Extractor) المعيار الفعلي لجمع الأدلة الرقمية السريع في بيئات ويندوز. تعتمد الأداة على مرحلتين أساسيتين: **الأهداف (Targets)** لجمع الأدلة من القرص الصلب بسرعة فائقة، و **النماذج (Modules)** لتحليل هذه الأدلة وتحويلها إلى تنسيقات قابلة للقراءة البشرية. الأداة مجانية للاستخدام غير التجاري وتحظى بشعبية هائلة في فرق الاستجابة للحوادث (IR).

## التثبيت (Install)

يمكن تحميلها من موقع `Kroll` (يتطلب ملء نموذج بيانات). وللحصول على أحدث حزم تعريفات الأهداف والنماذج، يفضل استخدام مستودع Eric Zimmerman: `https://github.com/EricZimmerman/KapeFiles`.

هيكل المجلدات النموذجي:
```
kape\
  kape.exe
  Targets\
    Compound\KapeTriage.tkape
    Live Response\
    OS\
    ...
  Modules\
    EZTools\
    Live Response\
    Microsoft\
    ...
  KapeFiles\           <- يتم استنساخ مستودع GitHub هنا
```

## المفاهيم الأساسية (Concept)

| المرحلة | العملية |
|-------|-----------|
| **الأهداف (Targets)** | جمع الملفات بناءً على أنماط محددة (مثل ملفات `.lnk` أو ملفات التعريف) باستخدام تقنيات تشبه Robocopy. |
| **النماذج (Modules)** | تشغيل برامج خارجية (EXEs) على الملفات التي تم جمعها لإنتاج تقارير بصيغ CSV أو HTML. |

يمكنك تشغيل الأهداف فقط، أو النماذج فقط، أو ربطهما معاً في أمر واحد (Target → Module).

## أوامر سطر الأوامر الشائعة

### التقصي السريع لنظام حي (عبر USB خارجي أو مشاركة شبكية)

```cmd
kape.exe ^
  --tsource C: ^
  --tdest E:\IR\%COMPUTERNAME% ^
  --target KapeTriage ^
  --module !ALL ^
  --mdest E:\IR\%COMPUTERNAME%\modules ^
  --mflush
```

| العلم (Flag) | الغرض |
|------|---------|
| `--tsource <drive>` | المصدر المراد الجمع منه (غالباً القرص C) |
| `--tdest <path>` | المسار الذي ستكتب فيه الملفات المجموعة |
| `--target <name>` | قائمة الأهداف (KapeTriage هي المجموعة الذهبية الشاملة) |
| `--module <name>` | قائمة النماذج (`!ALL` تشغل جميع النماذج المتاحة) |
| `--mdest` | مجلد مخرجات النماذج (التحليلات) |
| `--mflush` | مسح مجلد المخرجات قبل البدء |
| `--zip <name>` | ضغط المخرجات في ملف Zip واحد |
| `--debug / --trace` | نمط التفصيل لعرض الأخطاء |
| `--vhdx` / `--vhd` | حفظ المخرجات كقرص افتراضي (يمكن تركيبه لاحقاً) |
| `--scs` | تخطي نسخ الظل (Volume Shadow Copies) لسرعة أكبر ولكن دقة أقل |

### الجمع فقط دون تحليل

```cmd
kape.exe --tsource C: --tdest E:\IR\C --target KapeTriage --vhdx out
```

### تحليل مصدر تم جمعه مسبقاً

```cmd
kape.exe --msource E:\IR\C --mdest E:\IR\C\modules --module !ALL --mflush
```

## مجموعات الأهداف المفيدة (Target groupings)

| الهدف | ما يتم جمعه |
|--------|---------------|
| `KapeTriage` | الأهم (80% من الأدلة): `$MFT` والسجل، سجلات الأحداث، Prefetch، سجلات المتصفحات، سلة المحذوفات. |
| `Antivirus` | سجلات برامج الحماية (Defender, McAfee, إلخ). |
| `RegistryHives` | ملفات خلايا السجل (Registry) فقط. |
| `Browsers` | سجلات التصفح والذاكرة المخبأة لـ Chrome و Firefox و Edge. |
| `RemoteAccessLogs` | سجلات أدوات الوصول عن بعد مثل TeamViewer و AnyDesk. |
| `WebServers` | سجلات خوادم IIS و Apache. |
| `EmergencyTriage` | الحد الأدنى من الأدلة للأقراص ذات المساحات الضخمة جداً. |
| `OneDrive / Teams` | الذاكرة المخبأة لتطبيقات السحابة. |

## نماذج التحليل الهامة (Modules to know)

| النموذج | المخرجات |
|--------|--------|
| `EZTools/MFTECmd` | تحليل ملف `$MFT` إلى CSV |
| `EZTools/PECmd` | تحليل ملفات الـ Prefetch |
| `EZTools/RECmd_BatchExamples` | تحليل دفعي لخلايا السجل |
| `EZTools/JLECmd` | تحليل قوائم القفز (JumpLists) |
| `EZTools/LECmd` | تحليل ملفات الارتباط (LNK) |
| `EZTools/AmcacheParser` | تحليل ملف Amcache.hve |
| `Hayabusa` | البحث في سجلات EVTX باستخدام قواعد Sigma |
| `Chainsaw` | بديل سريع للبحث في سجلات الأحداث |
| `Loki` | تشغيل قواعد Yara على الملفات المجموعة |

## مسارات العمل (Workflows)

### وصول مهندس الاستجابة للحوادث (IR) للموقع

1. استخدام ذاكرة USB تحتوي على KAPE وتحديثات التعريفات.
2. تشغيل الأمر الشامل: `kape.exe --tsource C: --tdest \\fileshare\IR\$HOSTNAME --target KapeTriage --module !EZParser --mflush --zip $HOSTNAME`.
3. خلال حوالي 5 دقائق، تتوفر حزمة كاملة مضغوطة مع ملفات CSV المحللة على مشاركة الشبكة.
4. استيراد البيانات إلى أدوات مثل Timeline Explorer أو Splunk أو Excel.

### العمل على نطاق واسع (Fleet scale)

تعمل KAPE على جهاز واحد في المرة الواحدة؛ للجمع من آلاف الأجهزة، يتم دمجها مع أداة **Velociraptor** عبر ميزة `KAPE.targets.WindowsTriage`.

## المشكلات الشائعة وإصلاحها

| العرض | الإصلاح |
|---------|-----|
| `Could not find target file...` | اسم الهدف خاطئ (تأكد من وجود `!` قبل المجموعات) |
| النماذج لا تعمل | بعض النماذج تتطلب برامج خارجية توضع في مجلد `bin/` |
| أخطاء في نسخ الظل (VSC) | يجب التشغيل بصلاحيات SYSTEM، أو استخدم `--scs` للتخطي |
| المخرجات ضخمة جداً | استخدم `EmergencyTriage` واختر النماذج بعناية |
| الحاجة لمخرجات JSON | تقوم أدوات EZTools بالكتابة بصيغة CSV افتراضياً؛ يمكن تحويلها لاحقاً أو عبر Splunk |

## منظور المدافع والاستجابة للحوادث (IR)

تعتبر KAPE **الخطوة الأولى** في عمليات الاستجابة الحديثة. يتم تشغيلها فور صدور تنبيه أمني، وتُرسل المخرجات إلى "بحيرة البيانات" (Data Lake) للتحليل. الخطوات التالية عادة تكون:
1. جمع الأدلة عبر KAPE.
2. دفع المخرجات إلى أدوات مثل Autopsy أو Plaso لإنشاء خط زمني شامل (Super-timeline).
3. تشغيل Hayabusa على سجلات الأحداث المجمعة لرصد أي قواعد Sigma متطابقة.

## الأمن العملياتي (OPSEC)

- عمليات جمع الملفات الكبيرة قد تثير تنبيهات أنظمة EDR كنشاط قراءة/كتابة (I/O) غير طبيعي.
- يفضل التشغيل بصلاحيات SYSTEM واستخدام وحدة تخزين خارجية بدلاً من المشاركة الشبكية إذا كان نظام الـ EDR حساساً جداً.
- المقايضة بين الجمع الشامل (`KapeTriage`) والجمع المحدد (`ChromeFiles`) تؤثر على سرعة العمل والضجيج الناتج.
